# Notes for Claude (repository workflow)

Same release system as Iker's Tube.

- Layout: `web/` (Netlify), `3ds/` (devkitARM, `.3dsx` + `.cia`), `supabase/` (SQL + Edge Function).
- `VERSION` (repo root) = core version of the next release (MAJOR.MINOR.PATCH).
- Pushes do NOT publish anything. A devbuild (`v<version>-dev.N`) is created by hand: Actions > Build 3DSX + CIA > Run workflow on `main`
  (or `actions_run_trigger` with workflow `build.yml`, ref `main`). Do it when several commits have piled up, and before finishing a session.
  Each devbuild run prunes the list: only the newest 15 devbuilds of each version line are kept (`.github/scripts/prune-devbuilds.sh`).
  Pull requests only build (web + 3DS), nothing is published.
- Devbuild version = `max(VERSION, latest stable + 1 patch)-dev.<run number>`.
- `RELEASE_NOTES.md` = notes of the CURRENT devbuild only (English, plain text, no emojis). Replace its content with what the push adds.
- `STABLE_RELEASE_NOTES.md` = everything new since the LAST stable release (base = the commit the latest stable tag vX.Y.Z was built from;
  check it at the start of a session). Add each new feature to the list. When the owner publishes a stable release, rewrite the file for
  the next one: keep the intro line and the Installing section. English, plain text, no emojis.
- Stable release: Actions > "Stable release" > Run workflow on `main`, type the version (for example 0.1.0), optional draft. It reads
  `STABLE_RELEASE_NOTES.md`. Afterwards bump `VERSION` if needed.
- "Releases maintenance" workflow: `backup` (archive every release), `prune`, `republish`, `restructure` (needs RELEASES_PAT).
- GitHub secrets for the 3DS build: `AUTH_SUPABASE_URL`, `AUTH_SUPABASE_ANON_KEY`, `GAME_SUPABASE_URL`, `GAME_SUPABASE_ANON_KEY`.
- Compile the 3DS locally before pushing: `docker run --rm -v $PWD/3ds:/src -w /src devkitpro/devkitarm make` (needs `3ds/source/config.h`).
- 3DS UI preview without a console: see `3ds/preview/README.md` (renders every screen to PNG on the PC). Use it after any UI change in `3ds/source/ui.c` or `app.c`.
- 3DS auto update (`3ds/source/update.c`): reads https://api.github.com/repos/IkerPlays/BlocksyApp/releases, so every release must keep the assets named `Blocksy.cia` and `Blocksy.3dsx` and tags like `v0.1.0` (stable) / `v0.1.1-dev.N` (pre-release).
- Creating games is web-only and restricted by the server: `sessions.can_create` is set by the `game-session` function from `CREATOR_EMAILS` (default: the owner email). Do not add it to the 3DS.
- The 3DS updater and the README QR read the releases without logging in, so the repository must be PUBLIC.
- Avatar look is derived from the username with FNV-1a (web/src/avatar.js and 3ds/source/avatar3d.c MUST stay identical: palettes, hash, hair style). Emotes travel in player_state.anim (wave, dance, cheer, clap, sit; max 12 chars). The 3DS title version (makerom -ver) is the commit count (APP_VER) so every .cia is newer than the installed one; keep fetch-depth: 0 in the build jobs.
- Web game preview without Supabase: web/preview/README.md.
- Web v2: `web/src/` has i18n.js (es/en/pt/fr/de; every UI text through `t()`), social.js + social-ui.js (friend requests, DMs, notifications; AUTH RPCs in `supabase/auth/social.sql`),
  music.js (playlist from `web/public/playlist`, `playlist.json` generated by `web/vite.config.js`), sky.js/world.js (day-night, terrains), script.js (sandboxed Worker scripts for the editor),
  pwa.js + `public/sw.js` + manifest. Game rules (allow_build/allow_chat) are enforced in the GAME RPCs (`supabase/game/v2.sql`). The 12-color palette is shared by web/game.js and 3ds ui.c.
- Web preview: `web/preview/README.md` (shot.cjs renders worlds and pages). 3DS preview needs `source/avatar3d.c` in the gcc command (see `3ds/preview/README.md`).
- Friends on the 3DS use the AUTH RPCs (send_friend_request, my_requests, respond_friend_request, remove_friend, messages) and need an email login (not QR).
- Shop/BCoins: AUTH RPCs in `supabase/auth/shop.sql` (never let the client update `profiles.bcoins`; column grants enforce it). Web: pages.js `shop`, social.js wallet helpers; 3DS: `P_SHOP` in app.c + net.c wallet/shop RPCs.
- Studio (`/studio/<id>`): game.js `startGame({studio})` edit mode + `ui-layer` texts; scripts in JS (script.js worker) or Lua (lua-worker.js with fengari, vite aliases in vite.config.js replace Node-only libs). Voice chat: voice.js (WebRTC, Realtime broadcast signaling, no TURN).
- 3DS worlds: `3ds/source/world.c` mirrors `web/src/world.js` (plaza, obby, checker, void; same RNG for obby). Keep them in sync.
- PWA: `public/sw.js` is stamped with a build id by vite.config.js (`__BUILD__`); updates wait for the user (`applyUpdate()` in pwa.js).
- 3DS toasts/modals: citro2d clips depth above 1.0 and ui_text adds +0.5, so never call `ui_set_depth` with more than ~0.45.
- STORE (3rd Supabase project): shop catalog + games list (`supabase/store/schema.sql`). Wallet/inventory stay in AUTH; buying = `shop_quote` (STORE, HMAC-signed) -> `shop_redeem` (AUTH). GAME keeps only `game_rules` (`game/v3.sql`). Web env `VITE_STORE_SUPABASE_*`, 3DS `STORE_URL/STORE_ANON_KEY` (secrets `STORE_SUPABASE_URL/ANON_KEY`); without them the legacy paths (shop in AUTH, games in GAME) are used.
- Roblox-style Lua (v1.1): `web/src/lua/roblox.lua` (Instance system, services, task scheduler, signals, tweens, GUI) runs in `lua-worker.js` (fengari = Lua 5.3, 32-bit integers: no bit operators/large ints); `luau.js` transpiles Luau sugar (`+=`, `continue`, types, `{x}` strings) keeping line numbers; `scene-parts.js` draws parts/lights/GUI/leaderboard and detects Touched/click/prompt (messages: `new|prop|parent|del|touch|lb|hour...`, strings encoded `v:x,y,z` `c:r,g,b` `u:..`). Test headless with fengari in node (see git history of web/src/lua) and visually with a production build of `web/preview` (the dev server cannot run fengari).
- Studio 2: `web/src/studio-tools.js` (tools, undo/redo, structures, parts in `config.parts`, env panel); bulk blocks go through `api.placeBlocks` -> `place_blocks` (GAME v5, falls back to one by one).
- Dark Forest: `web/src/horror.js` + `world.js forest()` (web) and `world.c build_forest` + `forest_frame` in `main.c` (3DS); same seed gives the same trees and shards. Shared state = `interactions` events (orb/win/round/caught) and the `npcs` row (host lease, 3 s). 3DS draws trees as boxes (cells only for the cabin; `tgrid` holds trunk collisions).
- 3DS builds: `ui_build_ui`/`can_build` hide the palette in games without building; hats: `AV_HAT_ID` (avatar3d.c) must match `HAT_COLORS` (web/src/avatar.js).
- 1.4 modules (web): `collab.js` (Studio live co-editing over a Realtime channel whose name carries a random code; owner saves, guests never do), `components.js` (parts/scripts library in localStorage + export/import), `animator.js` (keyframes -> Lua TweenService block between `BLOCKSY-ANIM` marks; custom avatar emotes c1-c3 in `config.emotes`, poses in `avatar.js customPose`), `community.js` (clan, meetups, moderation pages; lazy-loaded from pages.js), `i18n-more.js` (translations merged under i18n.js; `tests/i18n.test.mjs` fails if any of the 11 languages misses a key or a {placeholder}).
- 1.4 SQL (all AUTH unless noted): v16 weekly missions + seasons (+ STORE v16 season items, price 2e9 so they cannot be bought), v17 clans/meetups/dm-media bucket, v18 moderation (`staff` table, bans enforced by triggers + `game-session` function) and visit counter (`game_visit`, `game_visit_counts`, `blocked_content`). The client hides blocked games; bans are server side.
- 3DS 1.4: `sfx.c` (synthesized effects on ndsp channels 1-4; music uses 0; row "Sound effects" in settings), `audio.c` (music), new worlds desert/caves/city in `world.c` (must stay identical to `world.js`; check by dumping cells from both), `net_game_visits`/`net_hide_blocked`/`net_visit` in net.c. Local syntax check: gcc -fsyntax-only with the stub headers (see git history of this session) because docker is not available.
- Tests: `npm test` in `web/` runs lua, anim, collab and i18n tests. Roblox-style `Tool` objects (hotbar) live in `roblox.lua`; mouse clicks reach scripts through `DISPATCH.mouse`.

- 3DS updater (rewritten): `update_core.c` (pure: versions, API/Atom parsing, SHA-256; test `3ds/tests/update_core_test.c`, see command in its header) + `update.c` (resumable download via `net_download_from`, verifies size/SHA-256 from the GitHub asset `digest` before `AM_FinishCiaInstall`, .3dsx `.new` -> `.bak` swap + rollback, `version.txt` news toast). New 3DS: `APT_CheckNew3DS` raises draw caps in `main.c`.
- 3DS Studio parts: `net_fetch_parts` (net.c, `games?id=eq.X&select=parts:config->parts`) on entering a game; `parts[]` in main.c are drawn by `draw_part` (rotated cuboid, ball, cylinder, alpha, Neon glow) and collide through `part_solid` inside `solid_at`; a spawn part moves `world.spawn`. Adaptive quality scales the draw cap by frame time (`q_adapt`). `audio_hold(true)` pauses music while updating.
- 3DS preview with main.c: compile it separately with `-Dmain=blocksy_main -c`, link it with preview.c/stub.c (stub.c has update_*/audio_* stubs) and run from `3ds/` (`BLOCKSY_PREVIEW_PARTS=1` draws demo parts).
- 3DS sky: `GameInfo.sky` (config.sky) -> `g_skymode` in main.c (SKT/SKH/DIM tables); the forest keeps its own night. Decor (hills, flowers) is visual only.
- 3DS native tests: `update_core_test.c` and `parts_test.c` (see the command in each header); `parts.c` is the pure reader of `config.parts` used by `net_fetch_parts`.
- Local 3DS syntax check: do NOT use `-w` (it hides implicit declarations even with -Werror=...); run `gcc -fsyntax-only -Werror=implicit-function-declaration` on every 3ds/source/*.c and read the errors (missing `#include <math.h>` etc. only fail in devkitARM otherwise). CI also runs the native tests before building.
- 3DS economy/social parity (net.c/main.c): `net_mission_add` (place_50, chat_5, play_10 batches every 20 s, obby_win), `net_earn_coins` ('play' every 5 min, 'obby' on race finish; the server caps per day), Home shows `net_my_clan`, `net_season` (level = xp/100) and `net_next_meetup`; the game list is cached in `sdmc:/3ds/blocksy/games.cache`.
- 3DS log: `blog()` (log.c) appends to `sdmc:/3ds/blocksy/log.txt` (48 KB cap); the updater logs checks, attempts and results there. Ask the user for that file when an update fails.
- 3DS Hills world (type 9): `world_hill_h` computes column heights with the web noise (verified by `tests/world_test.c` against `buildWorld('hills', seed)` sums); columns are drawn as boxes in main.c, trunks are cells, leaves are boxes. Islands (type 10) works the same way (`world_island_depth`, discs in `World.isl`); tests/world_test.c compares both with the web terrain.
- 3DS extras (main.c/app.c): pets and trails are drawn from the loadout string (`add_pet`, `trail_update`), chat speech bubbles (`bubbles[]`), Shop rows = items + daily missions + season tier + weekly missions (`RQ_MISSION`, `RQ_SEASON`, `RQ_WEEKLY`), `refresh_all` asks slow data (games list, missions, season, clan, meetup) every 90 s (`g_force_slow` is set by every user action) and only the players online every 12 s. Native tests (all run in CI): update_core, parts (+config, ui texts), world (web parity), json, fuzz; also compile preview with `-fsanitize=address,undefined` to catch memory bugs.
- Web tests also check that every literal `t('key')` exists and that every template/achievement has its texts; every scripted template is executed by the Lua harness.
